## Project background

SHOS (Smart Hospital Operating Subsystem) uses a fictional hospital setting to make operating-systems concepts interactive. It is an **educational simulator**, not a clinical or medical-record platform.

This project originated as **collaborative academic coursework**. The repository credits **Syed Muhammad Tafseer Raza Bukhari, Arzaq Ahmed Khan and Farzan Ahmed** as contributors to the original work. The public portfolio edition builds on that learning context.

## The problem

Abstract concepts such as scheduling priorities, memory replacement, event histories and access controls are easier to learn when their effects can be observed and explored through an interface.

## The implementation

The **Flask** and **SQLite** web application illustrates emergency-priority scheduling with Round Robin time slices for routine processes, an FIFO memory-frame demonstration, local sample record storage and a log of simulated events. A responsive interface makes the modules navigable on desktop and mobile.

## Engineering themes

- Modeling task scheduling and execution timelines.
- Simulating constrained memory and first-in-first-out replacement.
- Presenting operational data with responsive HTML/CSS/JavaScript.
- Saving fictional example records and audit events with SQLite.
- Separating interface presentation from educational simulation behaviour.

## Outcome and limitations

A locally runnable **teaching project** with fictional data. It does not manage real hospital operations, implement clinical prioritization, provide secure EHR storage or offer certified encryption. Base64 used in some sample fields is encoding—not encryption. Its original team contributions are acknowledged rather than claiming sole authorship.
